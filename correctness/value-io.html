Value I/O

Value I/O sits at the boundary between an exact value and the bytes used to carry it. A canonical route may choose one spelling, whereas a preserving route must retain an accepted spelling until an edit requires replacement. The distinction is small but strict: semantic equality licenses neither loss of a decimal scale nor rewriting of an unedited byte sequence.

This page fixes 31 laws. Laws 1 through 19 cover the canonical and default routes; Laws 20 through 31 give the corresponding concrete-syntax-tree (CST) obligations. The executable reference uses six routes: JSON, TOML, YAML, XML, CSV and TSV. The route parser and emitter are independent definitions in panproto_reference::value_io, and the bounded enumerator supplies byte strings of length at most two, every Unicode scalar as a one-scalar string, numerals with at most two digits and exponent from −1 through 1, exact integers at and beyond the i64 boundary, the special decimals and the non-finite binary64 values, sequences of length at most two, and a fixed temporal lexical product.

Write Pr​(b) for parse(r, b), Er​(v) for emit(r, v), and Cr​(b) for parse_cst(r, b). A byte sequence is accepted on route r when Pr​ returns a value. A value is representable on r when Er​ returns bytes. A CST value is the pair (v,b) of its parsed value and exact source bytes. Byte equality and string equality below are ordinary sequence equality; no normalization is implicit.

The executable fields name the closest bounded reference witness and production property witness. Several production witnesses do not compare their results with the independent reference on the same generated input; for those laws, the named commands do not by themselves establish agreement between production and the reference.

Canonical emission is a section of parsing

Statement

For every route r and value v for which Er​(v)=b, reading b under the route’s declared scalar kind returns v. For strings, booleans and nulls this is Pr​(Er​(v))=v, and so is it for integers on JSON, TOML and YAML. On XML, CSV and TSV an integer is cell text, so it is read under the signed 64-bit integer kind. Big integers, exact decimals and binary64 values are read under their respective numeric kinds, and temporal values are read under the lexical form carried by the value.

The production certificates quantify over the always-compiled complement-free JSON, XML, CSV and TSV routes: every exact decimal of the numeral scope, every one-scalar string, the exact integers at and beyond the i64 boundary, the special decimals and the non-finite binary64 values. Each production round trip through the matching reader is compared with round_trip. The reference operation remains defined on TOML and YAML; the certificates exclude their feature-gated production CST readers, and the string certificate reads each production TOML token with the reference TOML grammar instead.

Open JSON objects also admit the reserved Value::Blob carrier. L-value-io-19 fixes its canonical bytes and shows that the public JSON parser recovers the identical blob value. This is the structured-value instance of the same section equation in the production route; the scalar reference enumerator does not model structured values.

Outside the domain

The law makes no claim when emission returns a typed refusal. NotRepresentable covers a noncanonical big-integer representation; null on TOML, XML, CSV and TSV; CSV strings containing a comma, quote, carriage return or line feed; booleans on the three text-cell routes; XML decimals with a positive or structurally excessive scale exponent; XML strings holding a scalar outside XML 1.0 Char; noncanonical NaN payloads on TOML, YAML and XML; TSV strings containing a tab or line break; and temporal values rejected by L-value-io-5. NonFinite covers every special decimal and every non-finite binary64 value on JSON, CSV and TSV. LimitExceeded covers a big integer whose spelling exceeds the 64 MiB output allowance.

Definitions used

The functions Pr​ and Er​ are defined above. A typed numeric reading applies the route’s numeral dialect with ScalarKind::BigInt, ScalarKind::Decimal, ScalarKind::Float { bits: 64 } or, for an integer on a text-cell route, ScalarKind::Int { bits: 64, signed: true }, rather than asking the open scalar parser to recover a representation-specific variant. The string spellings are those of L-value-io-2, and the reading grammars those of L-value-io-4.

Proof

  1. round_trip first calls emit; every refusal returns false, so only representable pairs remain.
  2. For a temporal value it recovers the carried lexical form, removes JSON string quoting when necessary, and applies parse_as. Equality with the original value is the return condition.
  3. For the three representation-sensitive numeric variants, and for an integer on XML, CSV or TSV, it applies exact dialect coercion under the matching scalar kind. The emitter first requires a big integer to equal its canonical exact-integer representation, then writes its exact digits. The decimal emitter preserves the exact representation and the binary64 emitter writes a shortest spelling. Successful coercion thus returns the original carrier.
  4. Every other emitted value is passed to parse, and round_trip returns true exactly when the parsed value equals v. The cases are these. A null or Boolean is written as the literal that parse matches before any other branch. An integer on JSON, TOML or YAML is written in decimal digits, a complete numeral token that exact coercion reads as the same Int. A string on JSON, TOML or YAML is written double-quoted with quote, backslash and every C0 control escaped, TOML also escaping DEL; parse_double_quoted inverts each escape, and every scalar written literally lies in the route’s literal set, which is every scalar from U+0020 on JSON, tab and every scalar from U+0020 except DEL on TOML, and tab and every scalar from U+0020 on YAML, in each case excluding double quote and backslash. An XML string is written with the five markup characters as predefined entities and carriage return as &#xD;, and a scalar outside XML 1.0 Char is refused; reading normalizes only literal line ends, of which a written string holds no carriage return, and the references then restore each escaped character. A CSV string holding no comma, quote or line break is written and read verbatim. A TSV string holding no tab or line break is written and read verbatim. Each case reads back v.
  5. The JSON tree writer starts the root at enclosing-container depth zero, increments the depth across every schema object or list, and increments it once more for an open extra field. Nested Value::Unknown objects and Value::List arrays add one at each container. Every value at depth 128 is refused, matching the parser. A blob at depth d also contains a ref object and its $link string, so it is admitted exactly when d+2<128. The exact four-member object is recognized before the generic object case, and its link, media type and unsigned size reconstruct the original Value::Blob. Law 19 compares the source and reparsed trees under structural instance equivalence, checks the recovered blob directly, and checks exact JSON bytes after re-emission.

Canonical emission follows the route grammar or refuses

Statement

For every route r and value v, Er​(v) is either the route’s canonical scalar spelling or a typed refusal: NotRepresentable, NonFinite or LimitExceeded. JSON and YAML write null; JSON, TOML and YAML write lowercase booleans; strings use the route quoting of the Definitions; admissible temporal values use their display spelling, quoted on JSON; and numeric values use exact integer, decimal or shortest binary64 text. A big integer must equal its canonical exact-integer representation; otherwise emission returns NotRepresentable. An admitted big integer is written in its digits when they fit the 64 MiB output allowance, else in the exponent form {significand}e{zeros} on every route but XML, whose integer lexemes have no exponent, and is otherwise refused with LimitExceeded. XML finite decimals use positional notation with at most 1,048,576 fractional places. A special decimal is refused with NonFinite on every route, since no route reads a special spelling back as the same Decimal. Infinities and canonical NaNs use the route spellings inf and nan on TOML, .inf and .nan on YAML, and the XML Schema spellings INF and NaN on XML, with a leading minus sign when negative; JSON, CSV and TSV refuse every non-finite binary64 value with NonFinite, since their cells read numerals in the JSON grammar. A CSV string containing a comma, quote, carriage return or line feed is refused with NotRepresentable: the canonical CSV writer writes no quoted field.

The theorem above specifies the six-route reference. The production certificates compare the five always-compiled routes JSON, TOML, XML, CSV and TSV over exact-decimal emission on the complete bounded numeral scope, over every one-scalar string, and over the exact integers, special decimals and non-finite floats of the numeric scope. On TOML the writer chooses among basic, literal and multi-line string forms, so a TOML string token is compared by its reading under the reference TOML grammar, not byte for byte; the one multi-line token, for U+000A, is counted and skipped. The string certificate counts the refusals it observes on each route. Both the reference and the production readers read XML text under the XML Schema numeral dialect and CSV and TSV cells under the JSON one, so the spelling of every non-finite value on those routes is compared exactly. The decimal test contains a YAML branch only when tree-sitter is enabled; the default command below neither compiles nor certifies that branch.

Outside the domain

Every case without a spelling in the Statement is refused. Emission never substitutes a different value, drops a field of a value, or chooses a fallback route.

Definitions used

A canonical NaN is the positive or negative binary64 pattern named by CANONICAL_NAN_BITS or NEGATIVE_CANONICAL_NAN_BITS. JSON, TOML and YAML strings are double-quoted: quote and backslash are escaped, backspace, form feed, line feed, carriage return and tab use their named escapes, and every other C0 control is a four-digit \u escape. JSON writes those digits in lowercase and every other scalar literally, DEL and the C1 controls included. TOML writes them in uppercase and also escapes DEL as \u007F, which a TOML basic string may not hold literally. YAML writes every other scalar literally. XML escaping replaces the five markup characters with predefined entities and carriage return with &#xD;, since XML 1.0 Sec 2.11 reads a literal carriage return as a line feed, and refuses a scalar outside XML 1.0 Char. CSV writes no quoted field: a cell containing a comma, quote, carriage return or line feed is refused, though the CSV reader accepts RFC 4180 quoted fields. TSV has no quoting rule.

Proof

The match in emit handles null, Boolean, string and temporal cases before calling numeric_text. The string arms are quote, xml_quote, csv_quote and the TSV arm. quote escapes quote, backslash and every scalar up to U+001F, and on TOML also U+007F, which are the escape sets stated in the Definitions; xml_quote escapes the five markup characters and carriage return and refuses exactly the scalars outside the XML 1.0 Char ranges; csv_text refuses the four stated characters; and the TSV arm refuses its three forbidden characters. The temporal arm applies temporal. The numeric match is exhaustive over Int, BigInt, Decimal and Float: bigint_text first checks equality with the canonical exact-integer representation, then tests the digit count against the allowance before choosing the exponent form or LimitExceeded; the special-decimal arm returns NonFinite; the non-finite float arms write the three route spellings or return NonFinite on JSON, CSV and TSV; and every other variant reaches NotRepresentable. Thus a successful result has exactly the prescribed bytes, and every omitted case is a typed refusal.

Default routes distinguish null from absence

Statement

For a default route r and presence state p, presence(r, p) gives the following outcome:

RouteNullAbsent
JSON, YAML, XMLNullSyntaxOmitted
TOMLNullNotRepresentableOmitted
CSV, TSVNullNotRepresentableAbsentNotRepresentable

Thus an explicit null never becomes an absent field or cell. A route either writes its native null syntax or returns a typed null refusal. Conversely, an absent position is omitted only on a route whose structure permits omission; a positional table cell returns a typed absence refusal.

Outside the domain

The table covers default canonical emission. A configured tabular missing token and a CST-preserving route have separate contracts. The law also does not identify an empty string, an empty element or a zero-length byte sequence with either presence state.

Definitions used

Null is an explicit FieldPresence::Null. Absent is an omitted field or a missing positional cell. NullSyntax means JSON or YAML null, or an XML element marked with xsi:nil="true". Omitted means that no member or child is written. The two refusal outcomes correspond to EmitValueReason::NullNotRepresentable and EmitValueReason::AbsentNotRepresentable.

Proof

presence is a complete match on the product of six routes and two presence states. Its four arms are the four cells of the table after routes with the same behavior are grouped. Since the two input enums have no other variants, the match proves the table exhaustively.

Reading is the route-specific scalar function

Statement

Pr​ first requires UTF-8. JSON, TOML and YAML trim only surrounding whitespace admitted by their route grammars; XML, CSV and TSV retain it as cell text, XML after the line-end handling of XML 1.0 Sec 2.11, under which a literal carriage return, alone or before a line feed, reads as one line feed. JSON recognizes null, JSON, TOML and YAML recognize lowercase booleans, and YAML also recognizes Null, NULL, ~, and the empty plain scalar as null. XML expands predefined entities and character references with no declarations, CSV applies its doubled-quote grammar, and TSV accepts exactly text without a tab or line break. Quoted JSON, TOML and YAML strings use their route escape grammar and literal sets: JSON admits every scalar from U+0020 unescaped, DEL and the C1 controls included; TOML admits tab and every scalar from U+0020 except DEL; and YAML admits tab and every scalar from U+0020. These literal ranges exclude the double quote and backslash, which introduce delimiter and escape syntax. TOML recognizes a temporal only when L-value-io-5 admits it. On a numeric branch, a token reaches exact coercion only after it satisfies the route’s complete numeral grammar. YAML retains a nonnumeric unquoted scalar as text.

For the production certificate, r ranges over the always-compiled complement-free readers JSON, XML, CSV and TSV. The preceding paragraph defines the six-route reference function; the certificate excludes the feature-gated TOML and YAML CST readers.

Outside the domain

Invalid UTF-8, an ill-formed quote or escape, an invalid XML entity, and a forbidden TSV byte return Malformed or the route’s typed encoding refusal. JSON refuses a token outside its numeral grammar as Malformed. TOML sends tokens beginning with a digit, sign or dot to exact coercion and preserves its Fidelity refusal, including NotANumber for a malformed numeral; for tokens beginning with i or n, it maps a failed numeric reading to Malformed. YAML returns plain text whenever its unquoted scalar numeric reading fails. XML, CSV and TSV read their cells as text. The parser requires one scalar and does not recover a prefix.

Definitions used

The route dialects are JSON for JSON, CSV and TSV; TOML for TOML; YAML 1.2 for YAML; and XSD for XML. TOML and YAML single-quoted strings follow their distinct rules: a TOML literal string holds tab and every scalar from U+0020 except ' and DEL, with no escape, while a YAML single-quoted scalar writes ' doubled. JSON-style Unicode escapes require a valid scalar or a valid high-surrogate and low-surrogate pair. The double-quoted literal sets are RFC 8259’s unescaped, TOML 1.0’s basic-unescaped with its tab, and YAML 1.2.2’s nb-json; one modelled YAML scalar occupies one line, so a literal line break is refused there as well. An XML character reference is &# followed by one or more ASCII decimal digits, or &#x followed by one or more ASCII hexadecimal digits, then ;; a sign or any other byte is malformed.

Proof

  1. parse applies from_utf8, then the route-dependent whitespace rule. For YAML it refuses a carriage return or line feed remaining in the trimmed scalar, enforcing the one-line model before dispatch; escaped line breaks contain no such literal byte and remain available to the quoted-string reader.
  2. Its ordered match gives null and Boolean literals precedence over quoted strings, TOML temporals, YAML’s number-or-text choice, and route-valid numeral tokens.
  3. parse_string dispatches XML, CSV, TSV, single-quoted and double-quoted grammars. The XML arm replaces each carriage return line feed pair, then each remaining carriage return, by a line feed before it expands references, so a reference such as &#13; still yields a carriage return. parse_double_quoted rejects an unescaped interior double quote and dispatches a backslash to the escape reader. Every other scalar is literal exactly when literal_in_double_quotes holds for the route. Each helper consumes the whole string or returns Malformed.
  4. parse_number supplies the route dialect to exact coercion and preserves its typed fidelity refusal. The YAML caller handles a failed numeric reading by returning the original plain scalar as text. These cases exhaust the function.

Temporal representability is route dependent

Statement

For every well-displaying temporal t, temporal(r, t) holds on XML, CSV and TSV. It holds on JSON exactly when t is complete, and on YAML exactly when the offset of t is not local, since a YAML timestamp written without a zone denotes UTC and so cannot carry a local value. On TOML it holds only for finite values in one of three forms: a full four-digit non-negative-zero date with local offset; a full time with local offset; or a date-time having both full parts and a local, Zulu, extended fixed, or extended negative-zero offset.

The production certificate covers the five always-compiled emitters JSON, TOML, XML, CSV and TSV. The YAML arm is checked by the reference anchor only, because the YAML emitter is the feature-gated CST writer.

Outside the domain

A temporal for which display followed by descriptor-directed parsing changes the value is refused on every route. TOML additionally refuses infinities, reduced or truncated fields, non-four-digit years, negative-zero years and non-extended numeric offsets. JSON refuses incomplete shapes, and YAML refuses a local offset.

Definitions used

A full date contains a year of width four, a month and a day. A full time contains hour, minute and second. A complete temporal is the predicate implemented by Temporal::is_complete; display-parse agreement is panproto_reference::temporal::display_parse.

Proof

The function first tests display-parse agreement and returns false on failure. The TOML arm computes the full-date, full-time and offset predicates, then matches the temporal form against exactly the three cases in the Statement. The JSON arm returns is_complete, the YAML arm returns whether the offset differs from Offset::Local, and the remaining routes return true. Hence the characterization is exact.

The generic byte encoder and JSON route writer agree exactly

Statement

Let b be a byte sequence and let x be one of Base64, Base64Url, Base64Padded, Base64UrlPadded, Hex, Raw or Latin1. If the generic encode_bytes(b, x) returns text g, writing Value::Bytes(b) through the JSON value route under the same BytesText specification, at any value depth below 128, emits the JSON string g. If the generic encoder returns None, which can occur for non-UTF-8 input under Raw, the route returns EmitValueReason::NotRepresentable. The predicate bytes(g, r) witnesses equality between the generic text and the string recovered from the route token.

Outside the domain

The equality predicate applies only to successful text results. The production certificate checks the corresponding typed refusal separately. At a value depth of 128 or more the route refuses every value, bytes included, with NotRepresentable, whatever encode_bytes returns; the depth witnesses of L-value-io-19 certify that boundary for a scalar. Other value variants and non-JSON document layouts are outside this law.

Definitions used

The generic encoder is json_pathway::encode_bytes. The route writer is write_json_value_at_depth on Value::Bytes with a ScalarKind::Bytes(x) specification and a depth d. It first refuses when d≥128, then runs the round-trip guard json_value_roundtrips_at_depth, which for bytes encodes the value and reads the text back under the same specification, and only then reaches its byte arm. That arm delegates to write_json_bytes_scalar, which calls encode_bytes and then quotes the returned text as a JSON string. Route text is obtained by decoding that string token, so JSON quoting is not confused with the encoded payload.

Proof

bytes returns generic == route. In production, below depth 128 the round-trip guard passes whenever encode_bytes succeeds, by the byte-text law that decoding a successful encoding under the same BytesText returns the original bytes; when encode_bytes returns None the guard and the byte arm both refuse. write_json_bytes_scalar then extracts the BytesText specification and delegates to encode_bytes; a successful result is passed unchanged to the JSON string writer, while None becomes EmitValueReason::NotRepresentable. The production certificate enumerates every byte sequence of length at most two and every BytesText variant and checks this delegation boundary after decoding the emitted JSON token, applying bytes to each pair. It is exhaustive over the stated production scope, but it is not an independent second implementation of byte encoding. The independent I4 anchor instead fixes the equality predicate on the three witnesses left/left, left/right and right/left.

XML entity expansion is recursive and bounded

Statement

Given text t and a finite map D of internal entity declarations, xml_entity(t, D) scans from left to right and expands the five predefined entities, valid decimal and hexadecimal XML 1.0 character references, and declarations in D. Declared entities expand recursively. The result is defined only when every reference is complete and declared, every literal text run lies in XML 1.0 Char, declaration recursion is acyclic, nesting has depth at most 16, and the UTF-8 output has at most 1,048,576 bytes. Both bounds are inclusive: a chain of exactly 16 nested references and an output of exactly 1,048,576 bytes are admitted.

Outside the domain

The function returns Malformed for an incomplete reference, an invalid XML name, character-reference digits that are not all ASCII digits of the reference’s radix (a leading sign included), or a scalar outside XML 1.0 Char, literal or referenced; Undeclared(name) for a well-formed absent declaration; Recursive(name) when a declaration reappears on the active stack; Depth after the nesting bound; and Bytes after the output bound or a length overflow.

Definitions used

XML 1.0 Char contains tab, line feed, carriage return, U+0020 through U+D7FF, U+E000 through U+FFFD, and U+10000 through U+10FFFF. A character reference body is # and one or more ASCII decimal digits, or #x and one or more ASCII hexadecimal digits of either case. An XML name uses the NameStartChar and NameChar ranges implemented by xml_name_start and xml_name_continue. The nesting depth of a reference is the number of declarations being expanded when its replacement text is read, so a chain of n declarations, each but the last referring to the next, has depth n.

Proof

  2. It requires the next semicolon, then handles predefined entities and numeric references. character_reference reads the digits one byte at a time, accepting only ASCII digits of the reference’s radix with checked arithmetic, and then accepts exactly the character domain in the Definitions.
  3. Every remaining name is checked by the XML name predicate and looked up in D. The active stack detects recursion before the recursive call.
  4. A recursive call begins by refusing when the active stack has more than 16 entries; all produced text passes through append. These are exactly the success and refusal conditions in the Statement.

The canonical blob object reads back as the same value

Statement

For a blob reference r, media type m and size n, blob_writer(r, m, n) is the UTF-8 JSON object {"$type":"blob","mimeType":m,"ref":{"$link":r},"size":n}, where r and m are escaped as JSON strings. The generic JSON value route on Value::Blob { ref_: r, mime: m, size: n } emits those bytes when placed at an open object member whose parser value depth is at most 125. Parsing the emitted document recovers the identical Value::Blob, including when n is u64::MAX. Depth 126 receives NotRepresentable because the nested $link string would occur at the parser’s excluded depth 128.

Outside the domain

This law covers the canonical JSON tree route. A blob must occupy an open object member; placing it directly in a scalar node receives NotRepresentable because its object syntax would reparse as structure rather than as that node’s value. Binary blob contents, CID validation and preserving rewrites of noncanonical member order lie outside its domain. The older panproto_inst::parse JSON converter is also outside this route: it currently decodes JSON objects as Value::Unknown and serializes Value::Blob.ref_ as a bare string. The certificate neither calls nor repairs that legacy converter.

Definitions used

The canonical ATProto representation has four members in the displayed order. Its ref member holds a link object whose sole member is $link. The reader recognizes a blob only when the outer object has exactly the unique members $type, mimeType, ref and size, the $type string is blob, both text fields are strings, and size is an unsigned base-ten integer token in the inclusive range from zero through u64::MAX. A sign, fraction or exponent makes the object ordinary Value::Unknown, even when the token denotes a non-negative integral number such as -0 or 1e0. Other valid JSON objects also remain Value::Unknown; duplicate members receive the JSON parser’s typed DuplicateMember refusal.

Tree equality in the depth certificate is instances_equivalent. On these validator-admitted chain fixtures it requires the same root and schema root, the same node ids with equal anchors, values and extra fields, the same parent map and arc multiset, and the same child sequence at every parent. Arc records belonging to different parents may occupy different positions in the two global vectors because those positions do not affect the tree or its JSON form. The comparison still distinguishes a reordering of two children under one parent. Canonical WInstance byte identity is not claimed; byte identity below means equality of the emitted JSON documents.

JSON quoting escapes quote and backslash, uses the named escapes for backspace, form feed, line feed, carriage return and tab, and writes the remaining characters from U+0000 through U+001F as \u00xx. DEL, the C1 controls and all other Unicode scalars remain literal UTF-8.

Proof

blob_writer constructs the object independently with its local JSON string quoting function. Its final control branch is bounded by U+001F, which separates required C0 escaping from literal DEL and C1 output. The production certificate builds the corresponding Value::Blob, emits it through the public JSON route and compares the exact enclosing object bytes with the independent result. It then reparses those bytes and compares the recovered value with all three input fields. The four reference cases cover the two size boundaries. The string quoting is then settled exhaustively: for each of the 1,112,064 Unicode scalars, a blob whose link and media type are that one-scalar string is written by the production route exactly as blob_writer writes it and reads back as the same blob. Since the JSON string writer escapes each scalar of a string independently of its neighbours, agreement on every one-scalar string is agreement on every string, so the production escape set is exactly the one stated above. Fifteen reserved-shape near misses vary the required names and types, add a field, or leave the unsigned-integer grammar and range; two duplicate-member documents receive the parser’s refusal. A direct-node blob is refused because its object syntax would reparse structurally. The depth witnesses admit a blob at 125 and a scalar at 127, compare each reparsed tree structurally with its source, and recover the same JSON bytes on re-emission. The corresponding values at 126 and 128 are refused. Together, emission equality and parse equality instantiate L-value-io-1 for blobs.
