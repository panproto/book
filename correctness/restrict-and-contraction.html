Restrict and contraction

Restriction removes instance data that a migration does not carry forward, while contraction reconnects surviving nodes across the removed part. The construction is delicate for a specific reason: the view may contain nodes and edges that have no single source element. The implementation therefore compiles a schema-level plan first, evaluates that plan in a fixed stage order, and records enough residue to distinguish retained source data from synthesized presentation.

This page states thirteen laws. L-restrict-and-contraction-1 fixes the total edge image; L-restrict-and-contraction-2 and L-restrict-and-contraction-3 fix contraction planning and pair resolution; L-restrict-and-contraction-4 fixes graph execution. L-restrict-and-contraction-5 through L-restrict-and-contraction-12 state the cross-shape transport obligations. L-restrict-and-contraction-13 isolates the exact reachability claim.

Let S and T be source and target schemas, let m:S→T be a compiled migration, and let G be a finite source graph. A source vertex is endpoint-capable when it survives m. It is interior-capable when it is dropped by m or has a conditional-survival predicate; a conditional vertex is therefore both endpoint-capable and interior-capable. A source node survives when its anchor is endpoint-capable and, where required, its predicate accepts the node in the original graph. A realized pair (x,y) consists of surviving source nodes joined by a nonempty directed walk whose internal nodes include at least one dropped non-fan node and are all dropped non-fan nodes.

A transform’s output fields are the top-level fields that any of its operations may write, in operation order. At every surviving source anchor, each output field must be an attribute of the mapped target anchor. This condition includes unrealized anchors, inactive branches and temporary destinations; deleting a top-level field imposes no write obligation, and a nested update names its outer field. Updating a node’s own value imposes no field obligation. Production derives these outputs from transform syntax. The reference requires complete ordered output metadata from its caller, including writes that no supplied instance realizes.

Cross-shape statements quantify only over the validated common conversion image. Thus a tree, its graph encoding, and a table-shaped graph are compared only when the relevant encodings and schema-relative shape checks succeed; no law identifies malformed carriers merely because they can be stored by one raw representation.

The reference operations live in panproto_reference::restrict and panproto_reference::lens. The release carrier contains 57 schemas crossed with 27 survival classifications, 375 pair-resolution cases, 12,366 graph cases (each run bare and with decorated node payloads), 585 ordered child-binding words, nine column-fate cases, 70 tree cases, 16 Keep/Drop-between-survivors tree cases, and one fan-plus-expansion tree case. The tree-edit carrier adds 38 get words, 27 put words, two typed lowering refusals, one common late refusal checked through both source editors and both get_edit implementations, and one production-only late refusal.

The executable evidence for this page is a seven-test production/reference suite, four tree-edit tests, two lens-level tree-complement conversion tests and the reference tests they depend on.

The edge image is total and endpoint coherent

Statement

For every declaration-valid S, T, and m, edge_image assigns exactly one fate to every source schema edge e:a→b. If either endpoint is not endpoint-capable, the fate is Drop. Otherwise the fate is, in order: Keep(e') for the direct image; the result of pair resolution when an expansion path is declared for (m(a),m(b)); or Drop. A kept label is an edge of T from m(a) to m(b). An expansion is a path in T from m(a) to m(b), with one label per hop. The least incoherent image is refused during plan compilation, and an expansion with more than 216 hops is refused before a hop index is converted to u16.

Outside the domain

Invalid source or target declarations are refused before the edge image is compiled. A direct or expanded image that is absent from T, has the wrong endpoints, or has a label that does not join its adjacent anchors is refused as IncoherentEdgeImage. Failure to resolve an expansion hop is data in the plan (Unresolved), not a compilation refusal; execution reports that failure only when an instance edge has the fate. Base plan compilation checks source declarations, target declarations, edge images, contraction, then output fields. An undeclared output is refused as UndeclaredTransformField, with its source anchor, mapped target anchor and field; a dropped anchor imposes no output obligation.

Definitions used

The direct image of e is its explicit edge remap when present; otherwise it is an edge of T with the same kind and name between the endpoint images; otherwise, when e is the only source edge between its endpoints, it is the endpoint resolver entry. Pair resolution is defined by L-restrict-and-contraction-3.

Proof

edge_image traverses the ordered set of source edges once and inserts one map entry per edge. Its branch order is the order in the Statement. After computing a fate, it checks every Keep label against the endpoint images and calls coherent_chain on every expansion. The map therefore has the source edge set as its exact domain, and every non-dropped image is endpoint coherent. check_plan_expansion runs before the map is returned, which establishes the hop bound. The differential compares the reference map with production on all 57×27=1,539 identity-schema survival cases. Six additional compact witnesses isolate explicit remap, same-label fallback, endpoint resolution, expansion, unresolved expansion, and incoherent-image refusal. The existing boundary units independently pin acceptance at 65,536 hops and refusal at 65,537; the release differential does not duplicate a 65,000-element carrier.

The contraction plan is the trimmed dropped-interior relation

Statement

For each ordered pair (a,b) of endpoint-capable source vertices, the contraction plan contains (a,b) exactly when there is a directed walk from a to b with at least one internal vertex and every internal vertex is interior-capable. Its region contains exactly the source edges lying on some such walk. More explicitly, let Fa​ contain the interior-capable vertices reachable from a while staying inside the interior-capable set, and let Bb​ contain the interior-capable vertices from which b is reachable under the same restriction. An edge u→v belongs to the region exactly when (u∈Fa​∧(v=b∨v∈Bb​)) or (u=a∧v∈Bb​). The pair is bounded exactly when the subgraph of its region induced by interior-capable vertices is acyclic. Its target is (m(a),m(b)), and its resolution is L-restrict-and-contraction-3.

Outside the domain

The law applies after declaration validation. An incoherent pair label or expansion is refused as IncoherentPairImage; an overlong expansion is refused as ExpansionTooLong. An unresolved pair remains in the plan so that tooling can inspect it and execution can return a typed error if the pair is realized.

Definitions used

Endpoint-capable and interior-capable vertices are defined at the head of this page. A directed walk may repeat vertices and edges. Boundedness concerns only cycles wholly inside the interior-capable part of the region; cycles that require an endpoint do not make the pair unbounded.

Proof

The forward search reach(a, interior, succ) computes Fa​ by the usual visited-set fixed point. A pair is emitted only when an edge from Fa​ enters b, which is equivalent to the required walk. The reverse search computes Bb​. The filter used to build region is the formula in the Statement, so it retains exactly the edges that lie on an a-to-b walk through the intersection of forward and backward interior reachability. has_cycle repeatedly removes a vertex with no live predecessor; a finite directed graph survives that elimination exactly when it contains a directed cycle. The differential checks the production and reference pair relation, region, and bounded bit, then derives the same region independently by explicit walk enumeration.

Pair resolution has one fixed precedence order

Statement

For target anchors a′ and b′, pair resolution first takes resolver[(a',b')] when present. Without that entry, it takes the unique target edge from a′ to b′. If there are zero or several such edges and an expansion path is declared, it resolves each adjacent hop by that hop’s resolver entry and otherwise by the unique edge for the hop. It returns the expansion when every hop resolves, or the first failing hop with NoEdge or Ambiguous { count }. Without an expansion path it returns the original direct-pair failure. Resolution of an expansion hop never recursively consults another expansion path.

Outside the domain

There is no partial input domain: every pair of strings produces Label, Expand, or Unresolved. Coherence with a particular target schema is checked by the caller during plan compilation.

Definitions used

The unique target edge is the sole member of edges_between(a', b'), regardless of its name. The declared expansion path supplies intermediate anchors; its labels are derived by resolving adjacent pairs rather than stored independently.

Proof

resolve_pair calls resolve_edge first. That helper tests the resolver map before inspecting edges_between and returns a typed zero-or-many failure. Only that failure enters the expansion branch. The loop over consecutive anchors appends one resolved label per hop and returns immediately on the first failure. No call in the loop reaches resolve_pair, so expansion is not recursive. These branches are disjoint and exhaustive.

Graph restriction is staged Delta followed by contraction

Statement

On a successfully compiled plan and a graph in the fan domain, graph get evaluates in this order: non-fan nodes by ascending id; non-fan edges by ascending id; realized contraction pairs by ascending pair; fan nodes by ascending id; synthesized allocation by ordered synthesis key. A surviving node keeps its id, takes its target anchor, and receives its declared transform. A source edge whose endpoints survive follows the compiled fate: Keep retains id and position with the image label, Drop enters the complement, and Expand enters the complement while its path is synthesized. Every realized pair produces one labelled edge or one expansion path. Fans are evaluated after contraction. The first typed error in stage order is returned. Synthesized node and edge ids begin at their separate source floors, increase in synthesis-key order, and never equal u32::MAX.

Outside the domain

Output declarations are checked during compilation, before any instance is read. Plan mismatch is refused before evaluation. A graph outside the fan domain is refused at its least offending node. An undeclared instance label between surviving endpoints, an unresolved edge fate or pair, a predicate or transform refusal, a fan-label collision, an overlong expansion, and id exhaustion each produce the typed refusal at the stage and element specified by ErrorKey.

Definitions used

The fan domain consists of graphs in which every hyper-edge-shaped node and every source of a reserved fan edge participates in a well-formed fan. The node floor is zero for an empty node set and otherwise one above the greatest source node id, saturating at the reserved maximum; the edge floor is analogous. Synthesis keys distinguish direct contraction, source-edge expansion, and contraction expansion.

Proof

After compilation has checked declarations and output fields, get_with_plan validates the plan stamp and fan domain before it constructs Run. It records both floors, then calls nodes, edges, contract, fans, allocate, and record in the order stated. Each stage iterates a BTreeMap or BTreeSet, hence ascending key order. The node and edge stages implement the compiled fates directly. realized_pairs uses one visited set per surviving source and inserts pairs into an ordered set, so cycles terminate and duplicate witnesses collapse. Allocation sorts pending objects by synthesis key and draws from half-open ranges ending before u32::MAX. The 12,366-case differential runs every graph twice, once bare and once with every node carrying a value, a discriminator, a field, and an annotation. Each run compares the complete view, with every node’s id, anchor, value, discriminator, fields, position, shape, and annotations, and the complete complement, with its original fields and original values, together with synthesis keys, floors, and typed refusals. The decorated run also checks that every kept node keeps its payload. The carrier holds no predicate, transform, or fan, so the predicate, transform, fan, overlong-expansion, and id-exhaustion clauses rest on the stage argument above and on the pins of the other laws on this page, not on this differential.

Tree restriction uses the compiled edge image

Statement

Let the plan preserve tree shape, that is, let no source schema edge between two endpoint-capable vertices have the fate Drop. For a tree whose root survives and its graph encoding, tree restriction and graph restriction make the same decision for every direct source arc. Both read the fate from the compiled edge image. Keep preserves the carrier under its target label, Expand replaces it by the same labelled path, and Unresolved returns the same missing-or-ambiguous-hop refusal. Thus the tree view is the graph view of the encoding read back as a tree from the same root.

Outside the domain

The comparison requires a well-formed tree embedding and a plan valid for the same schemas and migration. Tree-specific root pruning is outside the graph result and is compared only after projecting the graph result back through the embedding.

A Drop fate between two surviving vertices is outside the domain, because there the engines decide the arc differently by design: the tree engine drops the arc together with the subtree below it, while the graph engine drops the edge alone. The counterexample is the source schema a→b, b→c with all three vertices surviving, a target without a→b and no expansion path for (a,b), so that a→b has fate Drop and b→c has fate Keep. On the tree 0(a)→1(b)→2(c) the tree view is the root alone, while the graph view keeps nodes 1 and 2 and the edge 1→2. What does hold outside the domain is weaker: the tree view is the component of the graph view that hangs from the root. The reference tree lens is undefined on such plans, and preserves_tree_shape is false exactly on them.

A tree whose view would give one node two values on a single-valued edge is also outside the domain. A named edge is a field projection and holds one value per parent, so tree restriction refuses with MultipleArcsOnSingleValuedEdge when arcs from two distinct source edges land under one parent on one named target edge. This happens in two ways: the edge map sends sibling fields to one edge, or contraction flattens a nested field onto a parent that already holds that field directly. A kept or expanded arc counts under the source edge it realizes, and a contracted arc under the source edge entering its child; arcs of one source edge keep their multiplicity and are not refused. The graph engine, whose instances may hold parallel edges, keeps such arcs as parallel edges with one label, so the two engines differ there by design and the tree refusal places the input outside the square, as root pruning does. The differential two_values_on_a_single_valued_edge_are_refused_on_both_sides pins both causes, a sibling merge and a direct field beside a flattened one, against the reference tree engine, together with the accepted single-source cases and the parallel edges of the graph route.

Definitions used

Two carriers are embedding-equivalent when tree-to-graph encoding identifies the tree nodes and arcs with the graph nodes and structural edges. “The same refusal” means the same typed cause and failing target anchors; wrappers may add shape-specific location data.

Proof

The reference tree_get is a native tree engine, not a call to graph get: it encodes the tree as its graph carrier, walks the tree breadth-first from the root, and shares only the compiled fates and pair resolutions with the graph engine. On a surviving parent and surviving child it applies the arc’s fate; on a dropped parent it contracts the child to its nearest surviving ancestor. First, without a Drop fate between survivors, every surviving node is reached: either its direct arc is kept or expanded, or it is contracted to its nearest surviving ancestor, which exists because the root survives. Second, in a tree the walk through dropped nodes into a surviving node is unique and starts at that ancestor, so graph contraction realizes exactly the pairs tree contraction joins. Third, kept arcs keep their ids, and synthesized carriers take the same synthesis keys from the same floors (L-restrict-and-contraction-8) in the same sibling order (L-restrict-and-contraction-12). The two views therefore coincide. Outside the domain, a Drop-fated arc (x,y) between survivors removes y’s subtree from the tree view, while in the graph view no edge enters that subtree from outside it: a contraction walk into it would have to pass through the surviving node y. So the tree view is the root component of the graph view.

The differential builds both plans from the same schemas and migration and checks every direct and expanded route on the 70-case tree carrier against the reference tree engine. On each of the 43 successful cases, and on the [Expand, Keep] witness, it also runs graph get on the tree’s graph encoding and checks that the graph view read back from the root equals the production tree view. Explicit drop and unresolved witnesses run through both graph and tree engines and compare the resulting view or typed cause. A further 16 cases cross the four Keep/Drop assignments to the arcs of a→b→c, with every vertex surviving, with four source trees. On the shape-preserving assignment the tree view equals the graph view and the reference tree view; on the other three the reference tree lens is undefined, the tree view equals the root component of the graph view, and 8 of the 12 cases show the engines’ views differ. The counterexample above is pinned separately.

Column fate is derived from the schema plan

Statement

For every surviving record, graph and table restriction remove or rename a cell exactly when the compiled cell plan removes or renames the corresponding attribute arrow. A dropped target vertex removes the cell. A retained attribute whose compiled edge image is renamed changes the cell name once. The fates place the transformed cells all at once; then each column that a declared field transform writes, and that the transformed record holds, takes the transform’s output, so a renamed cell whose image is an output column is overwritten there, as in L-lenses-12. Tree restriction obtains the same result by applying the corresponding fate to the child carrier. No engine derives column fate by inspecting instance labels after compilation.

Outside the domain

The law is stated for schemas that admit the relational attribute interpretation used to compile the cell plan. A disagreement between entity survival and graph survival is a plan-compilation refusal rather than an instance-level choice.

Definitions used

An attribute arrow is a schema edge from an entity vertex to its value vertex. A cell plan is the per-entity ordered map of Drop and Rename fates compiled from those arrows. For the default output check, an outgoing edge to a leaf declares an attribute regardless of its edge kind; the attribute takes the edge’s name or, when unnamed, its target vertex’s name. Protocol-aware compilation also accepts declared table columns with structured values.

Proof

  1. For each surviving source entity, cell_plan visits its columns in name order. A column’s attribute arrow has one compiled edge fate. A Keep image that is an attribute of the mapped target entity yields no action when its name is unchanged and one Rename otherwise; every other image yields Drop. Repeated child names bind an ordered list

Statement

When several non-self outgoing children of one element have the same field name and no own field shadows it, the child environment treats that name as repeated and binds it to a list in carrier order. An expression whose free variables include that repeated name is refused before evaluation as AmbiguousChildField. An own field takes precedence: shadowed child names contribute neither a child binding nor repetition. Tree and graph nodes contribute child-node scalar values; a table relation contributes its child rows, which have no node scalar value, so the repeated list may be empty. The common claim is repetition, order, duplicate preservation, and typed scalar refusal, not equality of payloads that one shape cannot represent.

A binding read through a child does not move the attribute. When an expression rewrites a field the element does not hold, reading its value from the one child the field names, the tree engines write the result back onto that child’s scalar value; the element gains no field of that name. Thus the view holds one value for the attribute, at the child where the source held it, and never a second copy among the element’s own fields.

Outside the domain

Self-loops do not contribute child values. A structural child that cannot be read in the required shape and a value outside the expression carrier produce their own typed predicate refusals.

Definitions used

For graphs, edge order is ordered_out_edges, ordered by position with edge id as the tie-breaker. For trees it is sibling arc order; for tables it is ascending target row id within the relation. The list preserves duplicates.

Proof

Tree put checks predicates and transforms before restoration

Statement

Given a complement produced by tree get, tree put admits a view only when every restored node satisfies its source survival predicate and forward replay reproduces the edited presence and value on every coordinate written or erased by either the baseline run or replay. Restoration follows the baseline-and-pullback rule of L-lenses-4: recorded residue supplies the baseline, independent coordinates retain the view’s edits, and available inverse operations carry changed outputs back to source coordinates. Predicate evaluation failures remain typed as predicate refusals. A replay mismatch on a default or computed coordinate is DerivedCellEdited; other transform mismatches are TransformNotInvertible. Put returns the first violation in its documented domain order and returns a restored source only after the complete check succeeds.

Outside the domain

Views with an id collision, edited synthesized carrier, unrepresentable edge, ambiguous reverse anchor, predicate refusal, transform replay mismatch or typed transform refusal, invalid key, missing required cell, or malformed fan are outside the put domain. Identity-envelope mismatch is refused before these clauses.

Definitions used

The restored node is the source candidate obtained from the view node plus recorded original anchor, fields, and value. A derived coordinate is a field introduced by the forward transform without source storage.

Proof

  1. Public tree put verifies the complement’s identity envelope before evaluating its domain. The domain checker compiles the plan, records structural violations and constructs the restorable counterfactual of L-lenses-5. It retains the structural report while filtering unrestorable view nodes, subtrees, arcs and fans together with shadowed residue. The candidate source used by the remaining checks is constructed without changing the caller’s view or complement.
  2. Reassembly combines each view node with its recorded source anchor, fields and value. The baseline’s executed transform trace identifies the coordinates owned by those operations. Unchanged outputs preserve their exact baseline source representatives; changed outputs pass backwards through applicable renames and declared inverses. Independent coordinates retain their edited presence and value. This is the baseline-and-pullback construction in L-lenses-4.
  3. Predicate checking evaluates the resulting source candidates in the same source context used by get. It checks the nonsynthesized nodes represented in the view, which are the restored nodes defined above. A false result yields SurvivalPredicateFails; an evaluation or binding failure yields its typed SurvivalPredicateRefused. Hidden dropped residue has no view node and is restored without a new requirement that it survive. The reference applies the same visibility and synthesis filters.
  4. Forward replay removes conditional-survival filtering while retaining the transforms, so a predicate failure cannot conceal a transform disagreement. For each restored view node, the checker compares presence and value on the union of coordinates written or erased by the baseline trace and the edited-source trace. It includes own values and supported scalar-child outputs. The last executed writer classifies a mismatch: a default or computation yields DerivedCellEdited, and another transform yields TransformNotInvertible. An edited derived output that replay reproduces through an independently edited input needs no additional inverse. Trace and replay failures remain typed refusals.
  5. Required-value, key and fan checks contribute their violations to the same report. Canonical sorting and exact-repeat removal determine its order, and public put returns the first violation or, when none exists, the restored source. The reference checks the corresponding candidates and projects its reports to native tree coordinates for the law comparison. The graph-square and tree-law certificates compare accepted sources and typed refusals on their stated carriers; the general case argument follows the domain stages above.

Tree edit translations commute with whole-state operations

Statement

Let s be the tracked source tree and v=get(s).view. The tracked complement c has the non-floor coordinates of that get and a historical floor H at least as large as its fresh floor. Initialization establishes this invariant, and successful raw calls preserve it. Write e⋅s for applying an edit word. A successful raw get_edit returns a word e′ such that e′⋅v=get(e⋅s).view. A successful raw put_edit returns a word e′ such that e′⋅s=put(e⋅v,c) and get(e′⋅s).view=e⋅v. Each successful call records the resulting source and refreshes its residue from whole-state get. These are endpoint equations; they do not identify distinct edit histories.

The comparisons keep the root, schema root, all node metadata and values, the complete arc sequence, and the complete fan sequence. Cached parent and child maps are derived from arcs. The complement’s allocation floor is at least its former floor and every floor reached by an intermediate primitive. Thus cancellation and undo can restore the source, view, and residue while retaining a higher historical floor.

Strict composition, input-support minimality, and translation of source undo have a narrower production certificate: the finite identity/static-projection leaf carrier defined below. On that carrier, lowering a translated whole word yields exactly the composite of the lowered translations of its primitives; both executions produce equal threaded complements. The leaf change agrees with the independent canonical leaf oracle, touches only input ids, and replaces a leaf only when the input replaces it. Source undo restores the original view and residue; it does not lower the historical allocation floor. Identity words translate to identity words. Delete followed by add remains replacement, including equal payloads, as L-edits-7 requires.

Outside the domain

A nonidentity raw call without initialization returns TranslationFailed. For a nonidentity call, the source edit, translated edit, whole-state operations, and endpoint comparisons must all succeed. Identity calls return identity without initialization or endpoint checks. A whole-state restriction refusal retains Restrict; other whole-state refusals retain their typed LensError in WholeState. A candidate word with a different endpoint returns TranslationFailed. These additional guards can refuse a primitive even when a different, more expressive translation exists. Every refusal leaves the tracked source and complement unchanged.

The guard checks a sequence as one atomic word. Its admitted domain need not be closed under prefixes: two field changes can restore the initial endpoint even when the first change alone omits a required computed-field update. No general composition or prefix-admission claim follows from successful endpoint checking. A delete of a missing source id returns NodeNotFound, including inside a sequence. Fresh allocation never reuses an id below its recorded floor.

Definitions used

The finite leaf carrier has root 0, visible leaf 1 and hidden leaf 2 initially carrying payload 0, fresh id 3, and payloads 0 or 1. Its source arc sequence is hidden leaf 2 followed by visible leaf 1, so the initial durable embedding assigns arc ids 0 and 1 in that order. The identity lens keeps both leaf kinds; the static projection drops the hidden kind. The view embedding restricts the source embedding to retained arcs and preserves both allocation floors; it assigns the retained visible arc source id 1 even when that arc is the view’s only arc. Its 19 source words are identity, two deletions, four insertions, four insert/delete cancellations, and eight delete/reinsert replacements. Both lenses give 38 get cases. All 19 words are put cases for identity; the eight all-visible words are put cases for projection, giving 27 put cases. The arc order is part of this certificate: reversing it makes visible-leaf replacement produce a different source arc sequence from whole-state put, and the raw endpoint guard refuses that word atomically. These words contain only leaf insertion and deletion under the fixed root. They have no conditional survival, field transforms, contraction, synthesis, fans, moves, or attribute updates.

Residue agreement here compares the whole-state complement after replacing its floor by the translator’s retained historical floor. It does not discard that floor from later allocation or assert equality with the original complement after cancellation. Strict composition on the finite carrier compares translating the same word whole with translating its primitives in order under durable embeddings. The independent oracle additionally composes canonical per-leaf changes. This does not assert that general production translation factors through canonical source-delta equality.

Proof

  1. Raw get first applies the input to a cloned source and computes the current whole-state view. It translates the word in staged state and applies that candidate to the view. The guard compares this endpoint with whole-state get of the edited source, using full tree identity. Success gives the get equation. Commit installs the edited source and recomputed residue, retaining the maximum floor; any earlier error discards staged state.
  2. Raw put applies the input to a cloned current view and computes whole-state put with the incoming complement. It applies the staged candidate translation to the original source and compares that result with whole-state put. It then recomputes get and compares the replayed view with the edited view. These checks give both put equations. Its commit and refusal behavior is the same as get’s. This argument checks a whole word, not each prefix independently.
  3. The independent leaf oracle represents a canonical change by optional before and after leaves at one id. Identity keeps each change. Projection filters each endpoint by its fixed leaf kind and records hidden leaves in the complement. Composition keeps the first before-leaf and the last after-leaf. Filtering thus commutes with composition in this structural carrier, including a hidden intermediate leaf. An empty/empty change disappears; a present/present change remains a replacement even when its payloads agree.
  4. The oracle acts independently at each id, so it introduces no new touched id. A filtered replacement has both endpoints only if the input has both. Its put admits all-visible changes and returns them unchanged; inversion exchanges their endpoints and get returns the inverse. These arguments concern structural leaf changes, not attribute changes that alter a survival predicate.
  5. The production differential compares all 38 get words and 27 put words with that oracle. Whole-word and primitive-by-primitive translations are lowered under durable embeddings and compared exactly; their threaded complements are compared separately. Get endpoints and residue are recomputed from edited sources. Undo distinguishes exact tree-edit inverses from cases whose exact inverse requires the canonical graph carrier. The inverse comparison uses the inherited source/view arc namespace and retained floors: each view insertion receives the same fresh arc id as its source insertion, and a deleted arc is restored under its original id. This certificate does not establish exact inverse translation between independently renumbered embeddings; the surviving before-state carries no correspondence for an arc already deleted. Cancellation and undo compare restored residue while retaining the historical floor.
  6. This finite certificate does not extend to general strict composition. Tree synthesis preserves source sibling order

Statement

Tree restriction emits surviving original siblings first, in their source order. It then emits synthesized attachments in ascending SynthKey order. Thus synthesis does not occupy the source position of the arc that caused it. For source siblings [Expand(0→1), Keep(0→2)], the view’s root children are [2, synthesized]. Encoding the result as a graph and reconstructing the tree yields the same sibling sequence on the validated common image.

Outside the domain

The comparison requires a tree-reconstructible graph and a coherent source order. A fan’s child-label order is governed by the fan signature rather than ordinary sibling position.

Definitions used

The witnessing attachment is the first edge on the breadth-first witness path selected by ascending source edge id. Original sibling positions are the optional positions stored on source structural edges.

Proof

tree_get first appends kept arcs while walking the source siblings, then allocates pending synthesized material after sorting by synthesis key, and emits each parent’s children in ascending view edge id. That order is the claimed order for two reasons. First, a kept arc keeps the id of its source arc, and source arc ids are numbered in source sibling order. All of them lie below the edge floor. Second, synthesized edges take ids from the edge floor upward in ascending synthesis-key order. Hence kept arcs precede synthesized attachments, the kept arcs keep their source order, and the synthesized attachments follow SynthKey order.

For the re-encoding clause, graph encoding numbers a tree’s arcs 0,1,… in arc order and gives them no position. Reading a graph back as a tree lists each node’s children by ordered_out_edges, which sorts by position and then by edge id. With every position absent, that is arc order, so the read-back tree has the same sibling sequence as the encoded one. The differential compares the complete ordered reference and production trees, not unordered graph projections, on all 70 route/floor cases. On each of the 43 successful cases and on the [Expand, Keep] witness, it encodes the production tree view as a graph, reads it back from the root, and checks equality with the view. The explicit [Expand, Keep] counterexample to source-position insertion pins the observed [Keep, synthesized] order.

Contraction preserves and reflects dropped-interior reachability

Statement

Fix a successful get and ignore fan edges. For every pair of surviving source nodes x and y, there is a nonempty x-to-y walk whose internal nodes include at least one node and are all dropped non-fan nodes exactly when the view contains the label or expansion path synthesized for the realized pair (x,y). Thus contraction preserves and reflects dropped-interior reachability among all survivors. The statement concerns the contraction stage; a direct source edge with no dropped interior is governed by its edge fate and does not by itself witness the premise.

Outside the domain

An unresolved pair and a realized pair absent from the plan make get fail, so they produce no view to which the equivalence applies. No survivor pair is excluded: neither the proof nor the 12,366-case scope yields a pair at which the statement fails, so the law is stated over all survivor pairs.

Definitions used

A view contains the synthesized route when it contains the single Contract edge or every adjacent edge of the ContractExpand path named by that pair’s synthesis keys. The walk may repeat nodes; fan nodes are never internal nodes of it.

Proof

For preservation, let such a source walk exist. The per-source breadth-first search follows non-fan edges through dropped non-fan nodes, so it reaches y and inserts (x,y) into the realized-pair set. Successful get supplies the declared pair and a resolved label or expansion, and allocation inserts its synthesized route. For reflection, every synthesized contraction route originates in a realized pair. The breadth-first search inserts such a pair only after traversing a source walk from x through at least one dropped non-fan node to y, so the source reachability witness exists. Neither direction uses the declared region, so no narrower domain is needed. The differential derives the realized pairs again through realized_pairs_by_walks, over every survivor pair, and compares that census with the synthesized contraction routes on every successful get of the 12,366 graph cases.
