Keys and registration

Keys connect graph structure to identity. A key declaration says how to read a tuple, which equality each part uses, and where equal tuples collide; a reference declaration names a key that can resolve such a tuple. Registration then binds those declarations to closed theories and replayable composition recipes. The eighteen laws on this page make each part of that chain explicit, from reading a key through canonical registration.

A key has an id, an ordered sequence of parts, a role, a scope, and either an empty equality vector or one equality declaration per part. An empty vector means representation equality at every part. A path part is a finite sequence of schema-edge labels. A position part names an ordered edge. Key roles are Primary, Unique, Identifier, SortKey, and Index; the first three are resolvable uniqueness roles, SortKey imposes order without uniqueness, and Index imposes neither. Scopes are document-wide, global, or relative to the nearest ancestor of a named vertex.

Key parts read the declared value or return NULL

Statement

For a graph G, node n, and key K, key_value(G, n, K) returns one value per key part exactly when every part has a value. For a path (e1​,…,ek​), traversal follows matching schema-edge labels in edge-id order through e1​,…,ek−1​. At the last step, each frontier node independently contributes the non-null own values of its matching targets or, when that node has no matching last edge, its field named by the last edge. The first contributed value is the part value. The empty path reads n’s non-null own value. A position part for edge e first chooses the least-id ordinary incoming e-edge into n, orders that parent’s ordinary e-edges by (stored position, edge id, target), and returns the selected edge’s zero-based ordinal in that sequence. The stored position orders siblings but is not itself the returned key value. Parallel edges into the same target retain distinct identities throughout this calculation.

Outside the domain

The result is None when the start node is absent, a path has no successful frontier, a selected own value is absent or null, a last-hop field is absent or null, a position part has no ordinary incoming carrier edge, or its index does not fit i64. One missing part makes the whole tuple None.

Definitions used

An own value is Presence::Present(v) with v unequal to the value variant Null. An ordinary edge has neither reserved fan kind and joins two non-fan nodes. Edge and node maps are ordered by numeric id.

Proof

  1. path_value handles the empty path by own. For a nonempty path, each preliminary hop replaces the frontier by matching targets in map order.
  2. At the final label, the implementation makes the target-or-field decision separately for each frontier node and retains frontier and edge order. Thus one branch with a matching edge cannot suppress a later branch’s field fallback.
  3. A position part retains the id of the first qualifying ordinary incoming edge, sorts every ordinary sibling tuple (stored position, id, target), and finds the tuple with that id. This keeps parallel edges distinct before converting the selected ordinal to i64.
  4. The initial node lookup returns None when the start node is absent, including when the key has no parts. For a present node, Iterator::collect on Option returns a vector exactly when every part returns Some, proving tuple totality on the stated domain and NULL propagation outside it.

Key buckets implement declared equality and scope

Statement

For graph G, vertex name v, and key K, buckets(G, v, K) examines precisely the non-fan nodes anchored at v, in node-id order. A node with no key value is omitted. Under Within(a), a node belongs to the scope of the least nearest ordinary ancestor anchored at a; a node with no such ancestor is returned in the ordered outside list. Document and global scopes use no ancestor id. Every remaining node belongs to the bucket indexed by its scope and the canonical bytes of its tuple under K’s per-part equality. The bucket retains the first tuple and all member ids in ascending order.

Outside the domain

The operation refuses only while it keys an element: at the first node that has a complete key value and, under Within, an ancestor, it returns EqualityArity when a nonempty equality vector does not have one entry per part, and UnsupportedCollation(name) when that node’s string part requires a named SQL collation, whose comparison is deliberately left to the database. A key whose vertex has no keyed element thus returns empty buckets whatever its equality vector, as production KeyIndex::build does, and a named collation over a numeric part refuses nothing. A production value constructed with an invalid numeric carrier may instead return InvalidNumericRepresentation; such values are outside the well-formed finite reference carrier. A keyed value without canonical bytes, namely a Temporal that is not well formed (for instance a fixed offset of 1440 minutes) or a value that contains one, has no representation and no declared equality, and the reference refuses it with NoCanonicalBytes at the first keyed node that holds it rather than placing it in a bucket. Production refuses it with the same NoCanonicalBytes at the same node, in its bucket bytes, in validation (as the required incomplete reason NoCanonicalKeyBytes), and in resolution. Thus equality arity, named collation, and missing canonical bytes are the three typed refusals of both sides.

Definitions used

The nearest ancestor is found breadth-first by reversing ordinary edges one level at a time, excluding the start node; ties at the first matching distance go to the least node id. Tuple bytes are a length-delimited concatenation of the canonical equality key of each part, defined only on values with canonical bytes. Equal tuple bytes have equal declared-key behavior by L-keys-and-registration-8.

Proof

  1. The outer loop filters the ordered node map by anchor and non-fan shape, so it visits exactly the stated carrier in ascending order.
  2. L-keys-and-registration-1 omits NULL tuples. Breadth-first reverse traversal follows only ordinary arcs, so reserved fan incidence and arcs incident on reified hyper-edge nodes cannot supply an ancestor. Sorting each next frontier selects the least matching ancestor at the nearest level.
  3. The scope id and equality-key bytes form the ordered map key. Map insertion creates one stored tuple at the first member and appends every later member, preserving node-id order.
  4. Equality-vector expansion and equality-key construction are the only fallible calls, and both run inside the loop after a node’s key value and scope are known. Their errors are exactly the typed refusals in the outside-domain clause, raised at the first keyed node that meets them; a loop that keys no node raises none.

Canonical schema bytes separate the finite declaration carrier

Statement

For schemas in the finite declaration carrier, canonical_bytes is injective. It writes vertices, edges, hyper-edges, constraints, required edges, orderings, entries, keys, references, and target sets in declaration order. Ordered maps and sets use key order; sequences retain stored order behind a u64 length; each sum variant has a distinct one-byte tag; strings and schema edges use the canonical primitive layout. Each optional extension inside a reference (a nondefault variable binding, the standoff extension, and the reference envelope of guard, null match, null vertex, and scope chain) is introduced by the eight-byte little-endian marker 263, and the trailing target-set extension by the byte 0xff. Thus two schemas have equal bytes exactly when every represented declaration field is equal. A declaration without these extensions keeps the bytes it had before the markers were introduced.

Outside the domain

The statement concerns the finite reference Schema carrier. A larger production schema field absent from that carrier is outside this function’s type and is not claimed to affect these bytes. Guard values outside canonical value encoding, such as a Temporal that is not well formed, are represented by the reference writer’s declared empty fallback and are excluded from the injectivity claim.

Definitions used

A self-delimiting field has either fixed width or a length prefix. A tagged sum writes its variant tag before its payload. A code is prefix-free when no codeword is a proper prefix of another; a concatenation of codes, each chosen by the bytes already read and each prefix-free, is uniquely decodable. The exact declaration carrier has zero through three vertices, one vertex kind, one edge name, and at most three labelled edges. Its two key slots are absent or hold an owner/key descriptor built from five roles, the document, global, and vertex-relative scopes, and the six nonempty words of length at most two over Path([]) and Path([v0 -prop:e-> v0]). These atoms do not depend on the surrounding graph.

Proof

  1. Fixed order separates top-level fields, and a count separates every variable-length collection. Map and set order is canonical; within a collection, primitive encodings and distinct tags separate keys, variants, and payloads. A fixed-width field and a length-prefixed string are prefix-free, since a reader knows each one’s extent before reading its content, and a tagged sum is prefix-free when each variant’s payload is.
  2. An optional extension is the one place where the reader decides presence from the bytes rather than from a tag. Where an extension inside a reference is absent, the next bytes are a u64 length (the target vertex’s name after a variable or standoff source, the next reference’s id after a reference), the target-set byte 0xff, or the end of the bytes. A length is the length of an allocated Rust string, which is at most isize::MAX <263, so it never equals the marker; the marker’s first byte is 0x00, never 0xff; and the marker has eight bytes where the end of the bytes has none. The trailing target-set byte is followed by nothing when absent. Presence is thus decided by whether the next eight bytes are the marker, or for target sets whether any byte remains. This lookahead gives the extension layout a unique parse. The complete schema encodings need not be prefix-free: omitting a trailing target-set extension can leave a proper prefix of the encoding with that extension. The earlier one-byte marker 0xff failed this test, because a length whose low byte is 0xff begins with it: the regression pair below, two valid declarations whose binding and target name differ, encoded identically under it.
  3. Reading equal byte streams from the beginning thus gives equal counts and equal fields by induction over the layout. Applying this argument to every top-level field yields schema equality; determinism gives the converse.
  4. There are 1, 2, 15, and 130 structural graphs at vertex counts zero through three. At positive n, there are Dn​=30n(n+2) owner/key descriptors, hence (Dn​+1)2 labelled two-slot declaration contexts per graph.
  5. The certificate executes all 148 graphs, every descriptor in both slots, every directed one-axis transition, and every absent, same-owner, and different-owner second-key class. Because graph fields precede declaration fields and the untouched slot is encoded unchanged, equality of complete byte strings factors through equality of the executed graph and declaration components. The recorded multiplicities reconcile to 27,329,908 schemas.

Change classification is the stated backward-compatibility decision

Statement

Within the declaration-change carrier, classify_change(A, B) returns Identical exactly when A=B. Otherwise it returns Breaking when any of the following holds: a primary, unique, or identifier key is added to a vertex already present in A; a primary key is removed; the first primary key selected from an existing owner’s stored sequence changes to a different id or disappears; an existing key changes parts, equality, or role, widens its scope, or changes between distinct scopes of the same rank; a reference added to an existing holder is non-nullable or fails unresolved values; an existing reference narrows cardinality, nullability, or unresolved handling, or changes any other semantic field; a target set is new or gains a member or changes scope; or the entry sequence changes. Adding a sort key or index does not add an instance-admission obligation and is BackwardCompatible, as are removals of non-primary keys and the other nonidentical declaration changes not listed above. Reordering keys without changing the selected primary, and adding or removing an empty owner entry, are nonidentical changes but impose no new admission obligation.

Outside the domain

The independent decision requires distinct key ids within each owner in both schemas and unchanged structural graph fields, apart from the explicitly tested entry sequence. Duplicate key ids cannot be represented by the owner/id maps used in this decision and are outside its oracle domain. Other declaration validity is not required by the finite descriptor carrier. Other vertex, edge, hyper-edge, constraint, required-edge, and ordering changes belong to the production classifier’s larger domain. The finite reference function remains total on its data type, but its result outside this declaration-change carrier is not an oracle for production behavior.

Definitions used

The five roles make different uniqueness, identity, ordering, and resolution promises. Thus every role-to-role change fails closed as breaking. Scope ranks are 3 for global, 2 for document, and 1 for within; distinct scopes at one rank count as a tightening in either direction. The selected primary is the first primary key in an owner’s stored sequence, the choice used by an unnamed reference. Removing any primary key fails closed because it removes an identity and resolution guarantee, even when another primary remains first. A directed one-axis transition adds or removes one descriptor, or changes only its role, scope, or part word. The finite carrier assigns fixed key ids to its two slots and stores them in id order; raw permutations and empty owner entries have separate controls.

Proof

  1. Structural equality is tested first and gives exactly Identical. key_is_tightened is the disjunction of changed parts, equality, role, greater scope rank, and unequal same-rank scopes; reference_is_tightened is the corresponding disjunction over every reference field.
  2. Ordered-map scans detect added, removed and changed declarations exactly as stated. Removing a primary is breaking independently of its slot or other declarations. A separate scan compares the first primary ids in stored order, while preserving owner presence and key sequence distinguishes harmless changes from equality. An addition on an old vertex is breaking exactly for the three uniqueness-bearing roles; sort keys impose only an advisory order check, and indexes promise no uniqueness or resolution. The separate target-set predicate detects a changed scope or any new member. The final entry comparison refuses an entry-sequence change.
  3. Each descriptor contributes one add, one remove, four role changes, n+1 scope changes, and five part changes, giving Dn​(n+12) directed transitions. The second slot is either absent, owned by the changed key’s vertex, or owned by another vertex. Since its declaration is identical before and after, classification is congruent under that untouched context; the same argument applies to the unchanged structural graph.
  4. The differential executes every graph, descriptor transition, slot, and nonempty second-key context class. The certificate’s multiplicities sum to n∑​graphsn​2Dn​(Dn​+1)(n+12)=816,223,680, which is the full labelled two-slot classification carrier. The added removal rule is independent of the untouched slot. A changed first-primary selection in this sorted carrier can arise only from an already-breaking addition, primary removal or role change; thus it introduces no extra dependence on that slot.
  5. A separate 28-case same-input matrix holds the structural context fixed while changing equality, reference addition and removal, each reference semantic field, target-set membership and scope, or the entry sequence. It checks both directed relaxation pairs and the explicit entry refusal against production.

Each shape theory is closed and composes with its schema theories

Statement

The instance theories for tree, graph, table, and flat shapes typecheck without undeclared symbols. Composing each instance theory with every schema theory in its registration group over the declared interface reports every InclusionIsMorphism and UniversalIdentity check as passed, with no failed, incomplete, or inapplicable record.

Outside the domain

Caller-supplied open theories remain outside this claim. Composition may report Inapplicable { OpenTheory } for such a theory. This law concerns the closed in-tree theories used by protocol registration.

Definitions used

A theory is closed when every sort and operation used by its declarations and equations is declared in that theory. The tree and graph interfaces contain Vertex, Edge, src, and tgt; the table and flat interfaces contain Vertex. A total composition report contains applicable passed records for both inclusion-morphism and universal-identity checks.

Proof

  1. The W-type, graph-instance, functor, and flat theories each declare the interface symbols they use. Their coherence equations thus typecheck in the theory that contains them.
  2. Each registration group builds one explicit-identity diagram over its stated interface. Symbols outside the interface are rejected on a name clash rather than silently identified.
  3. The composition checker verifies every inclusion and the identity mediator. The per-shape tests require passed records for both checks, a passed report status, and a passed record (Passed or PassedByEquation) for every check kind, so no record is failed, incomplete, or inapplicable.
  4. The registered-theory reference test converts every theory each protocol registers into the reference model field by field, checks that the reference’s canonical bytes of the converted theory equal production’s, and runs the reference signature check on it. For each protocol’s schema and instance recipe it replays the recipe in the reference and composes the recipe’s one diagram step in the reference, requiring a passed report with every record passed and the registered theory’s canonical bytes. The generic production/reference differential separately establishes agreement of composition over its bounded span carrier.

Registration records replayable recipes and preserves the compatibility surface

Statement

Each built-in protocol records the exact composition recipe for its schema and instance theories. Statement

Statement

Proof

  3. A normalized output has neither endpoint U+0020 nor adjacent U+0020. Repeating the same operation thus leaves it fixed.
  4. The XmlNonCdata string branch compares these outputs, so its kernel is equality of normal forms.

Group-G declarations validate and encode without collisions

Statement

The complete key, target-set, and reference declaration carrier is valid exactly when the independent validate_declarations function returns Ok(()). Key ids are unique per vertex, equality arity is exact, and sort keys have a unique ordered carrier from their Within scope. A repeated key id contributes one duplicate defect, regardless of how many later declarations repeat it. Target sets are nonempty and satisfy the schema-level member conditions in L-keys-and-registration-13. A reference whose resolving key, or any member key of its target set, has role SortKey or Index is refused with KeyNotResolvable, under either on_unresolved policy; in this release no reference resolves through an Index key. Every reference names a present target of matching arity and a compatible edge. A reference with no explicit target key selects the first declared Primary key; a key-value reference with neither resolves through the empty key, so a nonempty source is refused as an arity mismatch against zero parts. A target-set virtual edge starts at the reference holder and expands to a declared edge for every member. Inline references redirect through a target set. Variable binders name identifier keys of the target vertex itself and use one binding mode. A target set is no vertex and declares no key, so a variable reference to a set names no binder and is refused as an unknown target, and a variable reference whose named target_key is absent is refused the same way although its binder would resolve it. For text constraints, standoff lengths are not inclusive; fragmented standoffs are many-valued over an ordered holder edge; guarded partitions have distinct representation values; referenced text and scope-via chains are typed and acyclic; and target-set references carry no redundant per-vertex key. A referenced-text declaration is invalid when any reachable suffix repeats a reference, including when it enters a cycle that does not contain the starting declaration. The production validator agrees on this declaration-local predicate and additionally checks that named vertices, paths, positional carriers, scope ancestors, and protocol-required edges exist in the production schema. Each validator returns every defect in its domain in deterministic declaration order and with the stated multiplicity. A reference to a target set whose only member key is missing yields TargetSetMemberMismatch followed by UnknownTarget; source arity is not inspected without a resolvable target. Canonical schema bytes distinguish every valid declaration in this carrier.

Outside the domain

An invalid carrier returns the nonempty ordered defect vector. Named SQL collation behavior at instance level is outside declaration validity; its name remains part of canonical bytes. Production fields absent from the finite reference carrier are outside the injectivity claim.

Definitions used

The independent declaration errors are EqualityArity, DuplicateKeyId, TargetSetNameClash, EmptyTargetSet, TargetSetMemberMismatch, SortKeyNotOrdered, KeyNotResolvable, UnknownTarget, ReferenceArity, InlineRequiresRedirect, InlineRequiresTargetSet, LengthInclusive, InvalidFragments, DuplicateGuard, EdgeMismatch, TargetSetHasKey, VariableBinderInvalid, BinderModeConflict, TextReferenceInvalid, and ScopeViaInvalid. Production splits UnknownTarget into UnknownTarget and UnknownTargetKey, renames VariableBinderInvalid to BinderNotIdentifier and ReferenceArity to ArityMismatch; and adds UnknownVertex, PathDoesNotResolve, PositionNotOrdered, EdgeRequired, and WithinNotAncestor for the graph-aware checks. These substitutions yield the 26 public KeyRefError variants. Representation equality determines duplicate guard values.

Proof

  1. validate_declarations appends results from key, target-set, reference, binder-mode, and guard passes in that order and returns success exactly when the vector is empty.
  2. Each pass traverses ordered maps and stored sequences and appends the defect corresponding to the negation of one condition in the Statement. A repeated-id set limits duplicate diagnostics to one per id. Reference validation independently exercises all five key roles, checks the virtual edge’s holder before its member expansions, and selects the first Primary key when no target key is named. It first reports a redundant target-set key and, for a variable reference to a vertex, a missing named target key. It then checks the resolving target, recording a separate unknown-target defect when the binder is missing. Only a missing resolving target stops the remaining target-dependent checks; a missing named key does not stop them when the variable binder resolves.
  3. The text-reference helper carries the active suffix through recursion, so every reachable repeated node is rejected. The scope-via helper similarly follows its named chain with a visited set. Thus both accept exactly the typed acyclic chains described above.
  4. Canonical writing gives every declaration sum a distinct tag, every collection a length, every map a canonical order, and every optional extension a marker that the bytes following its absence cannot begin with. The unique-decoding argument of L-keys-and-registration-3 thus applies to this declaration subcarrier.

Index keys never resolve references, and null-match mode determines occurrences

Statement

A reference whose resolving key has role Index is refused at declaration with KeyNotResolvable under both on_unresolved policies, so no schema that resolution accepts holds one and no pair is derived through an Index key. For a composite referencing tuple, NullMatch::Simple creates a resolution occurrence exactly when every part is non-NULL, while NullMatch::Full creates one exactly when at least one part is non-NULL. Thus an all-NULL tuple is absent under both modes; a partly NULL tuple is absent under Simple and unresolved under Full; and an all-present tuple is resolved or dangling according to the declared target key.

Outside the domain

The law does not assert uniqueness for an Index key. The well-formed Complement reference through an Index key, whose get adds no edge, is not part of this release; such a declaration is the typed refusal above. The law also does not implement MATCH PARTIAL, which is a typed protocol refusal before resolution.

Definitions used

A resolution occurrence is a holder element together with the tuple read from the reference’s declared source parts. An absent occurrence produces neither a pair nor a dangling record. An unresolved occurrence produces a dangling record containing the complete tuple, including its NULL parts.

Proof

  1. Declaration validation refuses every reference whose resolving key has role Index (L-keys-and-registration-15), whatever its on_unresolved policy, and resolution compiles only declarations that pass it. Thus no value equality, including equality of two absent index fields, can derive a pair through that role.
  2. Under Simple, the occurrence filter is conjunction over the tuple’s non-NULL tests. Under Full, it is disjunction. These formulas give the three null cases in the Statement.
  3. The filtered occurrences enter the ordinary target lookup. An equal all-present tuple derives one pair; an unequal all-present tuple is dangling. A partly NULL tuple enters that lookup only under Full, where it is necessarily dangling against an all-present target.
  4. The production/reference differential observes pairs and complement records through the complete TreeToGraph resolution operation. It does not infer these outcomes from a separate Boolean helper.

Lexical-space validation preserves the literal and reports ill-typed values as advisory

Statement

Let s be a stored literal lexeme and let d be its declared datatype. If the datatype table assigns d a kind, lexical-space validation reports a ValueConstraint diagnostic exactly when s does not coerce under that kind. If the table does not assign d a kind, validation reports UnsupportedDeclaration. Both findings are advisory: they preserve s and do not make an otherwise valid graph fail admission.

Outside the domain

Syntax errors remain parser errors. This law begins after a literal and its datatype have been parsed and stored. It does not claim that the general panproto value readers implement every datatype’s lexical grammar.

Definitions used

A known datatype is one present in the protocol’s value-kind table. A derived value is the successful result of coercing the stored lexeme under that kind. ConstraintSemantics::LexicalSpace compiles to an advisory ValueConstraint check.

Proof

  1. ValidationPlan::compile resolves the datatype through the edge named by the lexical-space declaration.
  2. A known datatype supplies the kind used by the compiled check. The check emits a value-constraint diagnostic exactly when coercion fails.
  3. An unknown datatype cannot supply that check and produces the typed incomplete reason UnsupportedDeclaration.
  4. Both branches have advisory requirement. Thus neither changes a passing report to failure, and validation has no operation that could replace the graph’s stored lexeme; the differential reads the lexeme back after validation.

An annotated format is preserved and checked only as advisory

Statement

For ConstraintSemantics::AnnotatedFormat, validation preserves the stored value and compiles every recognized format check with advisory requirement. A failed recognized check emits a ValueConstraint diagnostic without failing admission. An unrecognized annotation does not impose a required assertion. By contrast, the separate Format semantics may require the same recognized predicate.

Outside the domain

This law does not govern ConstraintSemantics::Format, nor a dialect that explicitly enables a format-assertion vocabulary. Those declarations may make a recognized format predicate required.

Definitions used

An annotated format is a named constraint whose semantics are AnnotatedFormat(family). Preservation means that validation leaves the graph value unchanged. The bounded executable carrier uses the recognized uuid predicate under both annotated and asserting semantics, and one unrecognized annotation. The reference recognizer reads RFC 9562’s textual form: 36 characters, hyphens at positions 8, 13, 18 and 23, and a hexadecimal digit of either case elsewhere.

Proof

  1. Compilation distinguishes AnnotatedFormat from Format before selecting the same family-specific predicate.
  2. The annotated branch fixes the check requirement to advisory. Thus a failed predicate records a diagnostic but leaves the report passing.
  3. The asserting branch uses required status, so the same failed predicate fails admission. This contrast observes the declaration rather than an identity helper. An unrecognized annotation names no predicate, so compilation adds no check for it and its value is neither reported nor refused.
  4. Validation borrows the input graph and returns a report. The bounded differential reads the graph after both checks and confirms that its string is unchanged.
